<objective>
Wire the existing OS-level `estimated_deadline` field to a real, role-gated write path and prove
the value travels the full stack: Técnico saves it in the budget screen, the engine persists it,
and every read serializer returns it.

Purpose: nothing in production writes this field today (check-in only clears it to `None` at
`api.py:2254-2255`), so every existing read site — Kanban, OS detail, public tracking, print
formats — renders an empty value. This plan opens the single write path they were all waiting for.

Output: new whitelisted endpoint `set_service_order_estimated_deadline`, the field added to the
backend read allowlist and both serializers, the TypeScript contract, the API client method, the
deadline input inside `TechnicalBudgetEditor`, and a new end-to-end check
`run_service_order_deadline_checks` wired into `run_foundation_checks`.
</objective>
