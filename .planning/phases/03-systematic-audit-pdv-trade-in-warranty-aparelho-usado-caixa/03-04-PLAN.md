<objective>
Implement AUDIT-05: make the used-device warranty a real, server-checked claim at repair time instead of a stored date nobody consults.

Purpose: 03-CONTEXT.md D-03 records the real-world flow — when a used device sold under warranty comes back with a defect, the counter today opens a repair OS and marks it no-charge entirely by hand, with no automatic verification. Grep confirmed zero references to Used Device Warranty anywhere in `frontend/api.py` or `service_order/*.py`: there is no link at all between the warranty and the OS today. **This is genuine new feature work, not test-gap closure** — it was flagged as a real scope extension during discussion and the user confirmed it.
Output: the check-in path looks the warranty up by IMEI/serial, marks a covered repair as no-charge automatically, lets an expired one fall through to an ordinary charged OS per D-04, and the engine refuses to charge an OS that carries the no-charge marker.
</objective>

**Two design facts established during planning that the executor must not re-litigate:**

1. **Why a new field instead of reusing `courtesy_warranty`.** 03-PATTERNS.md offered `courtesy_warranty` as a candidate. It does not work here: `policies.py:90` gates it behind `_field_became_true(doc, "courtesy_warranty") and not _user_is_manager()`, and `_field_became_true` returns True for a new document (`policies.py:185-186`). An Atendente performing check-in would therefore be rejected by the Gestor gate on every covered device. `courtesy_warranty` stays exactly as it is — the manager-approved exception for an EXPIRED repair warranty — and AUDIT-05 gets its own dedicated, evidence-backed marker.

2. **Why the policy validator must not call `consultar_garantia_usado`.** That function is role-gated to `WARRANTY_LOOKUP_ROLES` (System Manager, Tecponto Atendente, Tecponto Gestor). A Técnico saving a diagnosis on the same OS would be rejected. So: the **check-in path** calls `consultar_garantia_usado` (its roles are `CHECKIN_ALLOWED_ROLES`, an exact match for the lookup roles — verified during planning), while the **validate hook** uses the role-free shared helper added in Task 1.

Environment notes carry over from 03-01: run everything through `wsl -d Ubuntu -e bash -c "..."`; run `./scripts/dev-local-server.sh restart` after every Python change because the bench serves with `--noreload`; a doctype JSON change additionally needs a `bench --site local-ci.local migrate` before the new fields exist in the database; and a spontaneous container `ExitCode=255` is the known Docker Desktop host issue, so bring it back with `./scripts/dev-local-server.sh up` and retry rather than changing the code.
