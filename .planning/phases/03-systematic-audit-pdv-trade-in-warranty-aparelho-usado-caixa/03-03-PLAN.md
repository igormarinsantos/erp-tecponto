<objective>
Implement AUDIT-03: block completion of a trade-in evaluation whose condition checklist is not filled in — and, in the same phase, give the counter a real way to fill it, so the gate protects the operation instead of bricking it.

Purpose: 03-CONTEXT.md confirmed the genuine gap (zero occurrences of checklist validation anywhere in Python). 03-PATTERNS.md resolved the ground truth and the definition to use. Investigation during planning found one consequence that must be handled inside this plan: `_sync_checklist` auto-appends the expected rows with `result` BLANK, and no React or API path writes `result` today — so a gate alone would make every React trade-in approval fail with no way for the attendant to recover. The write path is therefore part of AUDIT-03, not a separate feature.
Output: a backend gate, a backend read/write path for checklist answers, the React wiring that uses it, and CI proof of both the blocked and the allowed case.
</objective>
