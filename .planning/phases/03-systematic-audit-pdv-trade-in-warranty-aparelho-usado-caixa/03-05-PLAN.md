  <what-built>
Two counter journeys changed in this phase, and both need a human verdict before the phase can be called done:
- **AUDIT-03** — a trade-in evaluation can no longer be approved while any condition-checklist row is unanswered, and the React "Nova avaliação de troca" modal now collects those answers.
- **AUDIT-05** — checking in a device whose used-device warranty is still valid now automatically produces a linked, no-charge repair OS; an expired warranty falls through to an ordinary charged OS with a recorded reason; and a no-charge OS can no longer carry a charge.

Everything else in this phase (AUDIT-01, AUDIT-02, AUDIT-04) is test coverage over behaviour that already existed and did not change what the attendant sees.
  </what-built>
  <how-to-verify>
Start the local server with `./scripts/dev-local-server.sh up` and open the app.

**Journey A — Trade-in with the condition checklist (AUDIT-03):**
1. Open "Nova avaliação de troca" and pick a customer, an iPhone, a model, an IMEI and a value.
2. Confirm the condition checklist rows appear in the modal, and that switching the device type between iPhone and Android changes which rows appear.
3. Try to submit with at least one row unanswered — confirm it is refused and the message tells you what is missing.
4. Answer every row, submit, then approve the value — confirm the approval goes through normally.

**Journey B — Used-device warranty at check-in (AUDIT-05):**
1. Check in a device whose IMEI/serial matches a used device sold under warranty that is still inside its window. Confirm the resulting OS shows it is a no-charge used-device-warranty repair and that the attendance note says so.
2. Try to put a priced line on that OS and save — confirm the server refuses it.
3. Check in a device whose used-device warranty has already expired. Confirm the OS is an ordinary charged OS and the note records that the warranty had expired.
4. Check in an ordinary device with no used-device warranty at all. Confirm nothing about the flow changed.

**Also confirm nothing regressed:** run one ordinary PDV sale and one ordinary cash-session open/close, and confirm they still behave as before.
