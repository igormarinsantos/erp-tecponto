<objective>
Close the phase the way this project's rite requires: prove the whole system still works, then look at it with human eyes before declaring anything done.

Plans 02-01 through 02-03 each proved their own slice with a targeted `bench execute`. This plan runs the complete foundation suite so the widened `_write_audit`, the migrated audit doctype, and the three new endpoints are exercised against every other check group in the same site and the same transaction sequence — the only place where a regression in the pre-existing User-scoped audit path, or a doctype-sync side effect, would actually surface. Then a human walks the real counter journey once.

Purpose: GEMINI.md §2.2 forbids declaring anything done without testing the real complete flow, and explicitly forbids delivering buttons that only appear on screen without executing the action or persisting the data. This phase ships three such buttons. GEMINI.md §4 names the CI pipeline the final integration truth — which matters here because local Docker/WSL2 on this host is chronically unstable (5.9GB RAM, tracked separately in AUDITORIA_SISTEMA.md), so a flaky local run must not be mistaken for a code defect nor allowed to hide one.

Output: a green full suite, a green frontend build, a green CI run, and a human sign-off recorded in the SUMMARY.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Merged phase code → the rest of the system | Three new write paths and one migrated shared doctype now coexist with ~60 pre-existing check groups; regressions surface only when they run together |
| Automated assertions → reality | A test suite proves what it was told to check; a human at the counter is the only check on what nobody thought to assert |
| Local run → integration truth | An unstable host can produce both false failures and, worse, a passing run on a stale container that never picked up the migration |
