<objective>
Expand the proven audit path from plan 02-01 to the phase's most security-sensitive field: the device access credential. An Atendente/Gestor corrects a wrong PIN/pattern/password on an already-created OS; the change is audited; and the audit row records only that the credential changed — never what it changed to, what it was, how long it is, or any fragment of it.

Then close EDIT-04 with an explicit regression proof rather than an implicit one: the edit capability structurally cannot reach `pickup_date`, `warranty_expiry` or `estimated_deadline`, and the delivered-OS backstop still holds.

Purpose: EDIT-02 requires the credential stay masked with an audit log; D-03 makes metadata-only audit content a hard rule, not a style preference, because GEMINI.md §1.2 subjects the credential to mandatory sentinel testing across every channel the OS surfaces through — and the audit log is now one of those channels. EDIT-04 is already satisfied by omission today (the `text_fields` allowlist never mentions the date fields), which is exactly why it needs a test: behaviour that holds by accident is behaviour that regresses silently.

Output: a metadata-only credential audit inside `update_service_order_entry`, sentinel and allowlist assertions added to `run_edit_audit_checks()`, and the access-audit log enumerated as a channel in the canonical `run_device_credential_non_leak_checks()` sentinel test.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| React client → `update_service_order_entry` | The operator-supplied payload carries the plaintext device credential across this boundary; everything past it must treat the value as write-only |
| `update_service_order_entry` → `Tecponto Access Audit` | A newly-created data path from a secret-handling endpoint into a persistent, permanently-readable-by-System-Manager store — the highest-risk edge this phase introduces |
| `update_service_order_entry` → `Service Order` document fields | The edit surface must not become a route to delivery/warranty date mutation |
